작품 메타(`[작품명]_00_meta.md`)는 시스템에서 가장 자주 참조되는 진행 상태 source. 그러나 메타가 사실과 어긋나 있으면 그 위에서 내리는 모든 결정·보고가 거짓이 된다.

**원칙 (둘 중 하나는 반드시):**
1. **메타를 그대로 믿지 말 것** — 메타 참조해서 보고·결정할 때 **실제 파일 검증 동반**.
2. **메타를 믿을 만하게 갱신할 것** — 메타 작성·갱신 시 사실 외 기록 X.

**Why:** 2026-05-12 OFFERING 메타에 "50화 완결 / Round 1·2·3 / 4-Gate 통과 / 07_final 복사" 허위 진행 기록 있었음. AI가 그걸 그대로 믿고 사용자에게 "이미 50화 완결됨" 보고 → 사용자 분노 ("청사진을 오늘 작성했는데 왠 최종고"). 사용자 핵심 룰: **"메타를 그대로 믿지 말던가, 아니면 그대로 믿을만하게 분명하게 업데이트를 하던가."**

**How to apply:**

**A. 메타 참조 시 (보고·결정·다음 단계 결정 직전):**
- 메타에 "완료 / 통과 / [x] / 복사 / 패치 / 라운드 N회" 등 진행 단어가 있을 때 → **실제 폴더·파일 검증 필수**.
- 검증 대상:
  - `05_episodes/` 폴더에 EP 본문 파일 실제 존재?
  - `06_reviews/` 폴더에 검토 보고서 실제 존재?
  - `07_final/` 폴더에 최종고 실제 존재?
  - 메타가 참조하는 파일 경로 (`06_reviews/round1/...`) 실제 존재?
- Glob·ls·Read로 빠르게 검증. **검증 없이 메타 내용을 단언하면 안 됨.**
- 검증 결과 메타와 실제가 어긋나면 → 즉시 사용자에게 보고 + 메타 정정 제안.

**B. 메타 작성·갱신 시:**
- 예측·계획·"~예정"으로 `[x]` 마크 X. 사실 외에는 `[ ]`.
- 변경 이력에 "작업 완료 / 통과 / 검증 / 복사" 단어 사용 시 **실제 결과만 기록**.
- 미진입 단계는 "미진입" 명시. 부분 작업은 "부분 진행" 명시.
- 작품 완결 단언("완결 ✅", "모든 단계 완료")은 실제 07_final 검증 후에만.

**C. 메타 정정 시:**
- 허위 기록 발견 시 즉시 정정 + "정정 기록" 섹션에 어느 부분이 어떻게 무효 처리됐는지 명시.
- 정정 후 메모리·다른 참조 문서에도 동일 정정 전파.

**핵심:** 메타는 절대 신뢰 source가 아닌 **보조 인덱스**로 취급. 실제 진행 상태의 source of truth = **파일 시스템 자체**.
