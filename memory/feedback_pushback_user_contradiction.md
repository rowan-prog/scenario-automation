# 무조건 수용 금지 — 반박 지점 짚기 (2026-07-02 사용자 명시)

**사용자 지시(원문 취지):** "내 말을 무조건적으로 받아들이지 말고, 반박 지점 있는 건 이런 식으로 짚어라."

**원칙:** 사용자 지시라도 그것이 ①확정된 장르/작품 엔진 ②앞서 준 지시 ③원작/소스 ④블라인드 증거와 **충돌하면, 조용히 따르지 말고 충돌을 짚어라** — 내 해석/근거를 붙여 확인받은 뒤 집행. 순종만 하면 사용자 본인의 실언·모순이 그대로 본문에 박힌다.

**실증(이 원칙이 통한 사례):** 사용자가 "여주는 강한 폭력/모욕 당하면 안 됨"이라 지시 → 내가 "그럼 EP7 계단 밀림·강제낙태·군중 모욕 비트와 충돌한다"고 짚음 → 사용자가 **"내가 뭔가 잘못 말한 듯"**이라며 규칙을 정정("안 당함"이 아니라 **"안 꺾임"** — 사건은 있되 여주가 안 무너지고 복수 연료로 흡수). 짚지 않았으면 엔진 자산(굴욕 누적)을 잘못 삭제할 뻔.

**Why:** 사용자는 빠르게 말하며 종종 부정확/과장/모순되게 지시한다. 무비판 수용 = 그 오류를 증폭. 짚기 = 사용자가 진짜 의도를 재확인하는 기회. [[external-ai-evaluation-individual-validity]] [[meta-trust-and-verify]] [[ad-hook-novelty-over-proven-trope]]와 같은 결(권위·주장보다 증거·정합).

**How to apply:** 지시 받으면 확정 엔진/앞 지시/원작과 대조 → 충돌·모호·과장 발견 시 **(a) 어디가 충돌인지 (b) 내 해석/권장 (c) 확인 질문** 형태로 짚는다. 단 트집이 아니라 진성 충돌만(false-flag 금지·POV 존중 [[pov-speaker-utterance-not-error]]). 짚은 뒤엔 확정 따라 집행.
