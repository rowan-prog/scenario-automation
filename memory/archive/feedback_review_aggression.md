# 규칙

페르소나 9개 구성은 작품 도메인을 충분히 커버. 그러나 **검토 자체가 "역할별 평가자" 모드로 돌면 결함을 발견하지 못한다.** 검토 프롬프트에 다음을 강제.

## 1. 의심 지점 사전 스캔 (최소 5건)
검토 시작 시 의심 지점 5건 이상 먼저 나열 후 검증. 5건 미만이면 검토 강도 미달.

## 2. 원문 FIND 인용 강제 (모든 판정)
🔴/🟡/🟢 등급 + 통과 판정 모두 다음 형식으로:
```
위치: EP[N] / S#[번호] / [Visual|Camera|DIALOGUE|FX]
원문 FIND: "<정확한 인용>"
왜 문제 (또는 왜 작동): <인용 근거 진단>
수정 필요 여부: 🔴 / 🟡 / 🟢 / 검토했으나 유지
```
추상 평가 (`"좋다"`, `"작동한다"`, `"자연스럽다"`, `"이대로 통과 가능"`) 금지.
**통과 판정도 원문 근거 없으면 무효.**

## 3. "검토했으나 유지" 1-3건 필수
의심해서 스캔했으나 검증 후 문제 아닌 것으로 판정한 지점을 별도 섹션에 기록. **"그냥 통과" 차단 장치.**

## 4. 취향 vs 결함 분리
- 취향 개선은 🟢 또는 "검토했으나 유지".
- 실제 결함만 🔴/🟡. 두 카테고리를 섞지 말 것.

## 5. 시청자 페르소나(08/09) "작동" 단독 통과 차단
시청자 페르소나의 "✅ 작동" 판정만으로 통과 불가. **05 (Commerciality) + 07 (Genre Pleasure) + 04 (Dialogue Voice) 중 최소 2명이 원문 근거로 재판정**한 결과를 동반.

## 6. 최종 verdict 3-tier (phase_7 4-Gate)
- **LOCK** = 즉시 최종고 확정 가능.
- **PATCH THEN LOCK** = 명시 패치 후 최종고 확정.
- **HOLD** = 패치만으로 부족 — 재설계 필요.
HOLD 잔존 시 4-Gate 진입 불가.

## 7. 전체 재작성 제안 금지
"이 회차를 다시 써야 함" 류 전체 재작성 제안 금지. **최소 수정 단위만 제안.** 재설계는 phase_3 청사진 단계.

## 8. 활성화 페르소나 재확인 (작품 타깃 정렬)
"전체 순차" 호출 시 활성화 페르소나는 작품 타깃 1개 시청자만:
- 남성향: 01-07 + 08, **09 비활성화**.
- 여성향: 01-07 + 09, **08 비활성화**.
- 혼합·전연령: 01-07만.
잘못된 시청자 페르소나 활성화는 잡음 + 타깃 상실.

## Why
검토 보고서가 "구조 작동·대사 자연스러움·큰 문제 없음" 류로 통과시키는 사례 누적. 페르소나는 도메인을 보지만 결함을 hunt하는 자세 부재. 이를 검토 프롬프트의 공격성 강화로 보완.

## How to apply
- phase_5 검토 시작 시 의심 지점 5+건 먼저 나열.
- 모든 등급·통과 판정에 원문 FIND 인용.
- "검토했으나 유지" 섹션 작성 (1-3건).
- phase_7 4-Gate에서 LOCK/PATCH/HOLD 3-tier 최종 verdict 강제.
- HOLD 잔존 시 phase_6 → phase_5 재검토.
