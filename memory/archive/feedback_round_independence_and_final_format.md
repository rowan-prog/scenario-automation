scenario-automation 검토 사이클(phase_5)·최종고(phase_7) 두 가지 필수 규칙.

## 1. 라운드 독립 검토 (Round Independence)

각 라운드는 이전 라운드와 **완전히 독립**. Fresh 검토.

- Round N은 Round N-1의 발견·판정·결과를 참조하지 않음.
- "이 작품을 처음 보는 마음"으로 검토.
- 이전 라운드에서 패치한 부분도 특별 취급 X — fresh 평가.
- 같은 결함이 다시 발견되면 정상 (패치 미충분 또는 새 ripple).

**Why:** 사용자가 2026-05-08에 명시 — "이전 ROUND와는 무관하게 완전히 새롭게 다시 한다는 마음으로 ROUND2를 진행해야한다." 이전 라운드 결과 참조하면 "이미 고친 거니까 OK" 식 편향 발생. 각 패치 ripple로 새 결함 가능 — fresh 검토만 잡음.

## 2. 최종고 = 단일 통합 MD 파일 + 검증

최종고는 **화별 분리 파일 X. 모든 화 순서대로 통합한 단일 MD 1개**.

- 경로: `projects/[작품명]/07_final/[작품명]_FINAL.md`
- 구조: 작품 정보 → EP1 ~ EP50 순서대로 통합 → 시리즈 종합
- 금지: `07_final/[작품명]_ep01.md`, `_ep02.md`, ... 식 분리 저장

**검증 (필수):** 통합 MD 작성 후 반드시 검증.
1. 파일 존재 + 적정 크기.
2. 모든 화 헤더 EP1 → EP[N] 순서대로, 누락·중복 없음.
3. 각 화 4-블록 양식 (Visual / Camera / Dialogue / FX) 일치.
4. separator 일관.
5. 헤더 (작품 정보) + 푸터 (시리즈 종합) 정상.
이상 발견 시 즉시 재생성.

**Why:** 사용자가 2026-05-08에 명시 — "최종고를 EP별로 하지마라. 어느 세월에 내가 이걸 통합하는가?" 사용자가 50개 파일을 직접 통합하는 부담 회피.

## How to apply

1. phase_5 라운드 검토 시작 시 이전 라운드 보고서 참조 금지.
2. 패치된 부분도 fresh 검토.
3. 4-Gate 통과 후 최종고 저장 시 단일 통합 MD 파일로 작성.
4. 기존 작품의 화별 분리 최종고는 통합 MD로 변환.
5. 라운드 한계 5회 — Round 5 도달 후에도 4-Gate 미통과 시에만 사용자 판단 요청 (그 외에는 자율 진행).
6. phase_5·phase_7·CLAUDE·PORTING에 등재됨 — 메모리 백업.
