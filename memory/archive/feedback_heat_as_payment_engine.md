## 3. 플랫폼 버전링 (납품 단계 분리)

> **"이건 원본 창작을 약화시키는 하드룰이 아니라, 납품 단계에서 버전링할 문제다."**
> **"원본은 강하게 설계하고, 광고용 / 앱 심사용 / 플랫폼별 컷다운 버전을 따로 만든다."**

### 워크플로우

```
원본 (강하게 설계) ← 창작 단계
  ↓
[납품 단계 분리]
  ├─ 광고용 컷 (광고 플랫폼 가이드)
  ├─ 앱 심사용 컷 (Apple·Google 가이드)
  └─ 플랫폼별 컷다운 (ReelShort·DramaBox 등별)
```

### 룰

- **창작 단계 = 원본 강하게.** 보수 기준으로 잠그면 매출 손실.
- **납품 단계 = 별도 버전.** 플랫폼 가이드에 맞게 컷다운.
- 원본 단일·납품 다중 — 컷다운은 광고 컷·페이월 컷 별도 운영.

### 적용 시점

- **phase_4·protocol_premium_pilot 집필 단계:** 원본 강하게 설계.
- **납품 시점:** `phase_d_platform_versioning.md` (향후 신규 prompt 검토) 또는 사용자 결정 시 컷다운.
