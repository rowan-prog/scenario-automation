**분량 줄이기(화당 550자 맞추기 등)는 설명을 깎는 일이지 재미를 깎는 일이 아니다.** 2026-10-06 사용자: "과도한 설명을 줄이면서 이어져야지, 재미가 줄어선 안 된다." / "왜 이런 오류가 생기나 ㅡㅡ"

실패 실물(36·39·40·41 러프 A·B, 2026-10-01): sonnet 1기에 "지우기만 · 꾸밈말·부사구부터"로 시켰더니 설명 대신 재미 살을 지웠다 — 아이가 할아버지에게 달려와 매달리는 문장 통째, '팔다 남은' 부스러기, '눈물을 참으며', '오늘 딴 면허'(합격 당일 면허를 날리는 아이러니), '처음으로 울음을 그친다', '두 목덜미'(둘 다 뜬 표식), '붉은 용의 불'(황금 불과 맞서는 그림). '끝내 버리라고'의 '끝내'를 꾸밈말로 보고 지워 "버리라고 소리치다가"라는 비문이 마지막 무료 화 절정에 남았다. 유닛이 "이어 읽기 확인 안 했다"고 보고했는데 메인이 글자 수만 재고 "이상 없다"고 넘겼고, 읽기 검사는 줄이기와 **동시에** 돌려 줄이기 전 원고를 읽었다.

**Why:** 글자 수가 목표가 되면 유닛은 지우기 쉬운 것(형용사·부사·동작)부터 지우는데, 숏폼 트리트먼트에서 그게 곧 재미다. 설명 문장(앞에서 한 말 되풀이·서술자 해설·"~라는 것이다")은 문장째라 안 건드린다.

**How to apply:**
- 줄이기 지시 = "깎을 것 = 되풀이 정보·서술자 해설·풀이 문장 / 남길 것 = 몸·동작·표정·아이 행동·가난·굴욕의 구체·감정의 첫 순간·인과 고리·「」 대사·첫/끝 문장". "꾸밈말부터 지워라" 금지.
- 줄인 뒤 메인이 그 파일을 처음부터 이어 읽는다(글자 수 확인으로 대체 금지). 읽기 검사(plain-reader)는 줄이기·수정이 **끝난 뒤** 돌린다 — 같은 파일 동시 실행 금지.
- A·B 세트는 한쪽을 고치면 짝 파일 같은 자리를 반드시 같이 본다(41B만 고치고 41A '제럴드는 손주를 기다리며' 방치 사고).
- **'쓴 사람만 아는 말' 판정 기준(같은 날 사용자 교정):** 후킹 장치이거나 장르 약속(시스템 창 괄호, 판타지 용어, 낡은 쪽지 같은 떡밥, 원작 말장난 개그)이라 시청자가 알아듣는 거면 결함 아님 — 고치지 않는다. 결함 = 인과가 끊겨 다음 문장이 안 서는 것, 앞에 나온 적 없는 지칭(42A·B 로그라인 "그 코치" — 남주는 패트롤 대원/일꾼으로만 소개됨)뿐. 넓게 잡아 고치기 목록을 부풀리지 말 것 = [[proposal-prose-five-checks]]의 "반대편 벽으로 튀지 말 것"과 같은 병.
