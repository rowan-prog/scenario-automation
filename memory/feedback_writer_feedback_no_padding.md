사용자가 "이 피드백 다듬어줘"라고 주면 **사용자 문장의 핀트를 그대로 두고 짧게 정리**한다. 항목을 늘리지 않는다.

**Why:** 2026-09-10 29번 작가 피드백. 사용자 초안은 4줄(무료 1~8·카운트다운 엔딩 유지 / 능력 무의미 / 1화 분노 방향 / 중국 냄새). 내가 낸 v1은 항목마다 "지금/문제/왜/어떻게" 문단 + 광고컷·결제 강의 + 4화 엔딩·7화·회복비·르네상스·은행카드 같은 소소 지적까지 붙였다. 사용자: *"무슨 컷 무슨컷 이지랄. 좆도 상관없는 걸 떨고 있고. 말투도 병신, 수정 전혀 필요 없는 … 주접 떠는 부분도 너무 많고. 핀트도 못잡고."*

**How to apply:** ①항목 수 = 사용자가 말한 수(+명시 요청한 것 하나). ②항목당 판정 1~2문장 + 대안 한 줄. 이유 설명 문단 금지. ③"컷·광고컷·결제·페이월 강화" 같은 매체 강의 어휘 0. ④수정 안 해도 되는 건 안 적는다(엔딩 형태·화별 처짐·숫자 현실성·미술사 오류 류). ⑤워싱은 이야기가 바뀌는 설정만(장소·회사 성격·거절 사유·상속 조건·값 낭독), 소품·어휘는 뺀다. ⑥말투 = 사용자 초안 톤 그대로. 본문 규격 = `config/30_writer_feedback_standard.md` §3. 관련 = [[writer-comment-standard]] [[fix-by-deleting-not-explaining]]

**추가 (2026-09-10 같은 날):** 워싱 지적은 두 층으로 갈라서, **용어·소품 이름·호칭·어휘 = 우리 번역/로컬라이징에서 처리(작가에게 안 보냄)**, **장소·인물 구성·행동 = 작가 피드백**. 사용자: *"우리가 알아서 로컬라이징 번역으로 해결 가능한 영역이 있고 안 되는 영역이 있어."* 그리고 지적 전에 그 요소가 우리 기획안에서 온 건지 먼저 확인한다(29: 골동품 매장·창구·예언·"심사 도장 > 의사 소견"은 우리 것).

**추가 2 (2026-09-10):** 사용자가 준 판단을 그대로 받아 적지 말고 **대본·트리트먼트 원문으로 한 줄씩 검증**하고 쓴다. 사용자: *"마냥 내 말을 피드백 그대로 적지 말고, 대본 내용과 내가 파악한 내용이 다를 수도 있으니 검증하면서 해라."* 29번 실증: "집안 사람들(할아버지·마이크·랜스)" → 랜스는 집안이 아니라 임원(기획안·대본 둘 다) → 고쳐서 씀. 검증해서 맞은 건 맞았다고, 틀린 건 어디가 다른지 사용자에게 먼저 말한다.

**추가 3 (2026-09-10):** 작가에게 가는 문서에 넣지 않는 것 — ①비유("판이 뒤집힙니다", "축", "팔려는 그림") ②우리 사정("저희 기획안이 잘못 넘긴", "저희가 번역할 때 고치겠습니다", "원작에도 있으니") ③작가 국적 언급("중국 드라마 문법", "중국 재벌가 이야기") ④의도 설명("제가 의도한 것과 다릅니다", "미국 타깃인 이유가 여기 있습니다"). 작가가 알아야 할 건 세 가지뿐: 지금 대본에 뭐가 있나 / 무엇으로 바꾸나 / 왜(한 문장, 시청자 기준). 사용자: *"메타적이고, 너만 알고, 중국 작가는 알 필요도 없는 말들도 너무 많고."*
