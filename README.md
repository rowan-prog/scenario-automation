# Scenario Automation

**AIGC 숏폼(세로형 드라마) 시나리오 제작 전 과정을 AI 워크플로우로 재구성한 재사용 파이프라인.**

기획안 → 집필 → 각색 → 검수 → LOCK → 배포까지 한 사람이 돌립니다. 사람이 판정하고, 나머지는 역할별 에이전트와 결정론 도구가 나눠 맡습니다.

## 무엇을 자동화했나

```
아이디어 → 러프 기획안 → 피칭 → 완성 청사진 → 집필 ─┐
                                                    ├→ 검수 → LOCK → 배포
      원작 각색 ─────────────────────────────────────┤
      외부 대본·피드백 인입 ─────────────────────────┘
```

각 단계는 문서로 고정돼 있고(누가 무엇을 어떤 모델로 하는지 포함), 사람이 하는 일은 **판정과 확정**뿐입니다.

| 단계 | 무엇이 도나 |
|---|---|
| 기획 | 원안 정합 게이트 → 훅·아크 → 트리트먼트 → 시놉·캐릭터 → docx 빌드 |
| 집필 | 진입 게이트(히트작 정독 강제) → 지시서 → 프로스 생성 → 채택 판정 |
| 각색 | 치환표 확정 → 델타 집필 → 치환 잔재·골격 드리프트 기계 대조 |
| 검수 | 기계 게이트 6종 → 콜드리드·레지스터·정합 에이전트 병렬 → 머지 |
| 배포 | 남의 PC에서 그대로 도는 패키지로 빌드 |

품질 판정을 사람의 감에 맡기지 않으려고, 실패할 때마다 그 실패를 **세는 기계 게이트**로 바꿔 붙였습니다. 예를 들어 한 작품이 여덟 번의 LOCK을 통과하고도 "TV드라마 같다"는 판정을 받은 뒤, 그 원인(공간 순회·인물별 대사 레지스터 편향)을 각각 `pacing_lint.py`·`register_census.py`로 계량화해 상설 게이트에 넣었습니다.

**동작** — 실제 제작에 사용 중입니다.

| | |
|---|---|
| 진행 작품 | 19편 (`projects/`) |
| 산출 문서 | docx **69**건 (기획안·트리트먼트·검수의견·번역본) |
| 대본 파일 | **150**개 (버전 포함) |

```bash
python tools/build_dist.py --no-assets --zip
```

받은 사람은 압축을 풀고 `SETUP.md` 대로 하면 같은 파이프라인이 그대로 돕니다.
