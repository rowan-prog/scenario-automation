# Phase 6 — 수술 (패치)

> **v4 (2026-06-05 전면 재작성):** 9-페르소나 전수 재검토 의무·매 라운드 전 화수 일괄·패치로그+전체 스크립트 2파일 산출·viewer 코드 자동 처방 라우팅 = 전부 폐기. 현행 = **1 pass + 외과 수술 · 쇼러너 통합 판단.** 운용 단일 진실 = `config/agent_operating_rules.md`.

## 역할

검수 지적(phase_5·외부 피드백)을 받아 본문을 외과적으로 수정한다. **수정은 작고 정확하다. 전체를 다시 쓰지 않는다.** 이 단계는 재작성 단계 — **쾌감·재미가 중심이다** (운용 룰 §0). 오류는 잡되, 모든 수정은 "이 장면이 더 터지는가"를 기준으로.

## 채택 판정 (순서 고정 — 운용 룰 §1·§6)

### 필터 0 — 엔진/쾌감 선판정 (모든 지적에 최우선)

이 지적을 반영하면 **장르 쾌감 엔진·막장 톤·결제 동력이 죽는가?**
- 죽으면 → 정합성 지적이라도 그대로 채택 금지. 객관 모순 자체는 고치되 **쾌감을 보존하는 방식**으로: 개연성 구멍은 한 줄/한 행동으로만 메운다 ([[easy-dopamine-over-logic]] — 절차·설명·장치 추가 금지).
- 외부 피드백은 막장-필터 선적용: 논리닫기·증거살리기·세련교체·중반처단형 = 기각 권고 (external-intake-evaluator).

### 필터 1 — 채택 (필터 0 통과 후)

- 공간/시간/소품 위치/인과 논리 모순 · 청사진 락 vs 본문 모순 · EP 간 캐릭터 상태 모순 · 비주얼 락 모순 · 언어 일원화 위반(한국어 잔존·헤더 메타).
- 천박 밀도 부족·훅 약함·체감 안 되는 승리·반복 피로·구어 어색 — 쾌감을 올리는 지적.
- **🎙️ 톤 의존 대사·미세 표정 의존 지문** (2026-06-08·AI 더빙+AI 영상·`feedback_ai_dub_tone_independent_dialogue.md`): 의미가 *톤*에서만 나오는 대사(반어·이중의미·의미심장·애매) → 톤-독립 단일 의미로 재집필 또는 진의를 V.O./다음 대사/행동으로 외화 (cue로 봉합 X). "묘한/복잡한/의미심장한 표정"에 핵심 의미가 걸린 지문 → 무성 insert + V.O.로 외화. **단 교체는 항상 더 직설/천박 쪽**(아래 수정 원칙)·말맛/시그니처 보존.

### 필터 2 — 거부

- production_guide Hard/Soft Lock 침범 · 핵심 쾌감/페이월 약화 · 캐릭터 voice/매력 약화 · 안전·밋밋 누적 처방.
- 거부 시 보류 사유 한 줄 기록 (대화 내).

## 수정 원칙

- **FIND는 실제 본문의 정확한 문장. 기억으로 쓰지 않는다.** REPLACE는 바로 붙여넣을 수 있어야 한다.
- 하나의 패치 = 하나의 문제. 새 문제를 만들 가능성이 있으면 보류.
- **상위 구조 결함을 대사 한 줄로 봉합하지 않는다** (구조 결함 = 재설계 판정 → 사용자).
- **교체 방향 = 항상 더 천박/직설/쉬운 쪽** ([[claude-voice-bias-vertical-failure]] — 세련/문학 방향 교체 = 역방향·웨이브→커튼 사건).
- **말맛 보존:** 캐릭터의 단언형 대사·짧은 명령형·시그니처 cadence = 캐릭터 정체성. 의미 명료화를 위해 cadence를 무너뜨리지 않는다. Soft Lock 영역(톤·대사 방식·인티머시 강도) 강제 표준화 금지.
- 캐릭터 매력을 약화시키는 수정·안전하지만 밋밋해지는 수정은 하지 않는다.

## 수술 후 (운용 룰 §6-7)

- **delta 재검수:** 전량 재라운드 금지 — 영향 EP × 해당 렌즈만 재투입. (예: EP08-09 수술 → cold-read는 EP1-12 구간만·fresh-eyes는 수술 비트 정합만.)
- 일괄 변환·대량 수술 시 = final-consolidator 기계 게이트 (깨진 패턴 grep·대사 word-diff).
- **버전 분기:** 메이저 수술(턴 단위·사용자 종합 피드백) 전 새 `FINAL_v{N+1}` 파일로 분기 (version-anchor).
- docs 환류는 하지 않는다 — LOCK 후 1회 (운용 룰 §7).

## 반복 한계

- 같은 지적이 3회 반복되면 → Soft Lock/취향 차이로 분류해 보류하거나 사용자 판단 요청. 무한 루프 방지.
