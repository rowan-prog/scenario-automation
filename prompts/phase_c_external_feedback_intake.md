# Phase C — 외부 피드백·시장 리포트·인사이트 처리 (2026-05-15)

## 역할

사용자가 주기적으로 제공하는 **외부 자료**를 우리 시스템 + 진행 작품에 반영·기각·보완·이관한다. 주 입력:

1. **외부 피드백** — 우리 산출물(스크립트·피칭덱·청사진)에 대한 외부 평가·피드백
2. **시장 리포트** — 플랫폼·트로프·정량 분석 자료 (DataEye·Omdia·플랫폼 공개자료 등)
3. **인사이트 자료** — 외부 AI 평가, 업계 노트, 트로프 트렌드, 신작 분석

## 핵심 원칙

- **자동 적용 X** — 모든 외부 입력은 **타당성 검증 → 분기 결정**
- **타당하면 반영, 타당치 않으면 기각, 부분 타당하면 보완**
- **시스템 갱신은 인사이트로만 — 외부 입력 그대로 룰화 X** (워싱 안 됨)
- 시스템 절대 목표 (북미 paid vertical 잘 팔리는 대본) 정합 검증 필수

## 입력값

- 외부 자료 (파일 경로 또는 사용자가 inbox에 두고 명시)
- 적용 대상 (전체 시스템 / 특정 작품 / 특정 페이즈)
- 사용자 의도 (단순 인사이트 / 적극 반영 검토 / 검증 요청)

## 실행 전 읽어야 할 파일

- `config/master_guide_v3.md` (절대 기준)
- 적용 대상 작품 메타 (특정 작품 한정 시)
- 관련 메모리 (자료 카테고리에 따라):
  - 외부 AI 입력 처리: `feedback_external_ai_input_handling.md`
  - 웹 리서치 정책: `feedback_web_research_policy.md`
  - 2026 paid vertical 시장: `feedback_2026_market_research_insights.md`
  - 위원 B (글·시장 이해): `config/evaluators.md` 3-0

## 처리 워크플로우

### Step 1. 자료 분류

| 카테고리 | 처리 우선 |
|---|---|
| **외부 피드백 (산출물 평가)** | 산출물 업그레이드 분기 |
| **시장 리포트 (정량)** | 트렌드·트로프 보강 또는 시스템 룰 갱신 |
| **인사이트 자료** | 메모리 보강 또는 무시 |
| **레퍼런스 작품 정보** | 히트작 라이브러리에 등재 |

### Step 2. 타당성 검증 (필수)

각 항목별 다음 자문:

1. **시스템 절대 목표 정합?** (북미 paid vertical 매출에 기여하는가)
2. **마스터 가이드 v3·CLAUDE.md·메모리와 충돌?** 충돌 시 어느 룰이 우위인가
3. **워싱 필요?** 외부 AI 출력물이면 워싱 안 된 상태에서 그대로 적용 X
4. **레퍼런스 작품인가?** 타깃 플랫폼 (ReelShort·DramaBox·NetShort·Flickreels·ShortMax)·6개월 이내 신호가 있는가
5. **위원 B (vertical 작가 시점)이 이 입력을 어떻게 평가할 것인가?**

### Step 3. 분기 결정

| 결정 | 처리 |
|---|---|
| **반영 (적용)** | 시스템·작품에 직접 반영. 메모리 등재 또는 prompt 갱신 |
| **기각** | 사유 명시 + 자료는 archive (재참조 가능) |
| **부분 반영 (보완)** | 일부 항목만 등재. 시스템 룰로 변환할 때 워싱 |
| **보류** | 추가 검증 필요. 사용자에게 보고 |

### Step 4. 산출물 업그레이드 (외부 피드백 한정)

외부 평가가 우리 산출물(피칭덱·스크립트·청사진)에 대한 것일 때:

1. **필터 0 — 엔진/쾌감 정합 선판정 (최우선·운용 룰 §1):** 이 피드백이 장르 쾌감 엔진·막장 톤을 죽이는가? 논리닫기·증거살리기·세련교체·중반처단형 = 기각 권고 (**external-intake-evaluator agent 막장-필터 위임 권장**).
2. **피드백 항목별 검토 (필터 1 + 필터 2)** — 메모리 `feedback_review_master.md` 채택 2 필터 동일 적용
   - 필터 1 (채택): 공간 논리·시간 논리·소품 위치·인과 논리·정합성·언어 일원화 (단 필터 0 통과분만·수정은 쾌감 보존 방식 = 한 줄/한 행동)
   - 필터 2 (채택 거부): production_guide·핵심 쾌감 약화·캐릭터 매력 약화·안전 밋밋 누적
3. **채택 항목 → 산출물 패치** (phase_6 외과 수술)
4. **거부 항목 → 사유 명시·archive**
5. **보강 항목 → 부분 패치 + 부분 사유**

### Step 5. 시스템 룰 갱신 (시장 리포트·인사이트 한정)

타당성 검증 통과 + 시스템 보완 가치 큰 경우:

1. **메모리 신규 등재 또는 기존 메모리 보강**
2. **phase prompt 갱신** (필요 시)
3. **CLAUDE.md 핵심 원칙 추가** (매우 큰 변경 시)
4. **MEMORY.md 인덱스 갱신**

### Step 6. 레퍼런스 작품 등재 (해당 시)

- 새 레퍼런스 작품 발견 시 → `config/hit_library/` 인덱스 갱신
- 작품명·플랫폼·정량·매핑 키워드·타깃·장르 추출
- 피칭덱 작성 시 자동 활용 가능

## 산출물 (token-diet 룰5 — 대형 보고서 폐기)

- 대화 내 한 줄 요약: **수용 N / 기각 N + 기각 공통점 한 줄** + 반영 위치 경로.
- 자료 archive — `inbox/` → `config/external_feedback_archive/[날짜]/` (필요 시). 별도 분류 보고서 파일은 사용자 요청 시만.

## 자율 진행 vs 사용자 확인

- **자율 진행:** 명백한 인사이트·자명한 트렌드·우리 룰과 정합하는 자료
- **사용자 확인:** 우리 룰과 정면 충돌하는 자료·작품 정체성 변경 자료·Hard Lock 변경 자료
- 사용자 확인 시 `PushNotification` 알람 발송

## 외부 AI 평가 처리 특수 룰

`feedback_external_ai_input_handling.md` 그대로 적용:
- **워싱 안 됐으면 직접 적용 X** — 인사이트만 추출
- 외부 AI가 "이게 좋다"라고 한다고 그대로 받지 말 것
- 우리 시스템·매출 목표 정합 검증 후 적용

## 시장 리포트 처리 특수 룰

`feedback_web_research_policy.md` 그대로 적용:
- 4 플랫폼 한정 (ReelShort·DramaBox·NetShort·Flickreels) + 보조 (ShortMax)
- 6개월 이내 신호 우선
- 정량 (조회수·랭킹·기간) + 매핑 키워드 형식으로 정리

## 히트작 라이브러리 갱신

- 새 레퍼런스 발견 시 `config/hit_library/` 현행 인덱스(current_hit_library.md)에 추가
- xlsx 직접 편집보다 별도 `config/hit_library/supplements/[날짜]_supplement.md` 권장 (검색·정합 용이)

## 핵심 한 줄

> **외부 자료 = 타당성 검증 후 분기. 시스템 절대 목표 정합 검증 필수. 워싱 안 된 외부 AI 출력 직접 적용 X.**
