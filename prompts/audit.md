# Audit — 시스템 정합성 검사

## 역할
프로젝트 산출물·시스템 파일·룩 변형 락·환류 로그·씬 수·소품 한도·메모리 일관성을 자동 점검한다. **읽기 전용** — 발견 시 보고만 하고 사용자 승인 없이는 수정하지 않는다.

진행 점검(`prompts/status.md`)과는 별개의 도구. 진행 단계만 보려면 status; 정합성을 보려면 audit; 둘 다 보려면 동시 호출.

## 호출 방식
- "/audit" 또는 "정합성 검사" — audit만.
- "/status /audit" 또는 "전체 점검" / "status audit" / "둘 다" 등 — status + audit 둘 다 순차 진행 (status 먼저, audit 다음).

별도 입력값 없음.

## 점검 항목 (6 카테고리)

### 1. Reference INDEX 동기화
- `config/reference_scripts/` 폴더의 실제 파일 목록 vs `INDEX.md` 등재 표 일치 여부.
- 등재되지 않은 파일이 폴더에 있으면 🔴 (자동 발견 안 됨).
- INDEX에 등재됐지만 폴더에 없는 파일이 있으면 🔴 (잘못된 참조).
- 권장 조치: 새 파일이면 AI가 정독 후 자동 등재 (사용자 승인 후).

### 2. 룩 변형 락 vs 스크립트 묘사 일치
- 청사진 12-7 룩 변형 락의 모든 변형이 등장 회차 스크립트에서 first-appearance 묘사가 실제로 있는가.
- 청사진에 미등재된 룩이 스크립트에 등장한 케이스 (즉시 🔴 — persona_06 검토 사항).
- 누락된 변형은 🟡 (회차 진입 전 보강 권장).

### 3. 환류 로그 누락
- 청사진 본문이 변경된 흔적 (캐릭터 캐논 보강·룩 변형 추가·관계 지점 변경 등)이 있는데 청사진 말미 "환류 로그"에 해당 줄이 없으면 🟡.
- 로그가 있는데 본문 변경이 없으면 🟢 (단순 환기, 무해).

### 4. 씬 수 표준 위반
- 각 에피소드 스크립트의 `S#` 헤더 카운트.
- 8씬 이상 → 🔴 (비표준).
- 7씬 → 🟡 (한도 위, 정당 사유 확인 — 페이월·대형 시퀀스만 허용).
- 6씬 이하 → 🟢 (정상).
- 1씬 다중 비트 의심 (씬 길이가 평균 2배 이상) → 🟡로 의심 보고.

### 5. 소품 한도 위반 (일반 소도구 한정)
- 각 에피소드의 신규 일반 소도구 도입 건수 카운트 (문서·열쇠·꽃·전화기·기기·식기·서류·일회용 도구·미장센 등).
- 회차당 3개 이상 → 🟡 (한도 위반, 정당화 확인).
- 회차당 5개 이상 → 🔴 (과다, 압축 권장).
- 캐릭터 정체성 장신구·핵심 무기·권능 도구는 카운트 제외.

### 6. 메모리 ↔ 시스템 룰 일관성
- 메모리(`~/.claude/projects/.../memory/`)에 등재된 feedback 룰이 step prompts / CLAUDE.md / PORTING.md와 일관되는가.
- 메모리 룰만 있고 시스템 파일에 없으면 🟡 (이식성 위반 — 시스템에 반영 필요).
- 시스템 룰만 있고 메모리에 없으면 🟢 (메모리는 백업이라 무해).
- 메모리와 시스템 룰이 모순되면 🔴 (즉시 사용자 확인).

## 실행 순서
1. `config/reference_scripts/` 디렉터리 vs `INDEX.md` 비교 (점검 1).
2. 각 작품 `04_blueprint_full.md`의 룩 변형 락 vs `05_episodes/` 스크립트의 first-appearance 묘사 비교 (점검 2).
3. 청사진 본문의 변경 가능 항목 vs 환류 로그 비교 (점검 3).
4. 각 에피소드 `S#` 카운트 + 평균 씬 길이 통계 (점검 4).
5. 각 에피소드의 신규 일반 소도구 도입 카운트 (점검 5).
6. 메모리 디렉터리의 feedback 파일 vs step prompts·CLAUDE·PORTING 검색 (점검 6).
7. 모든 점검 결과 표로 출력.

## 출력 형식

```markdown
# scenario-automation 정합성 감사 — [날짜]

## 종합 판정
- 🔴 즉시 수정: [수]건
- 🟡 약점: [수]건
- 🟢 정상: [수]건

## 1. Reference INDEX 동기화
- 폴더 파일 N개 / INDEX 등재 N개
- 미등재 파일: [목록]
- 잘못된 참조: [목록]

## 2. 룩 변형 락 vs 스크립트 묘사
| 작품 | 변형 | 등장 회차 | 묘사 상태 | 판정 |
|---|---|---|---|---|
| ... | ... | ... | ✅/🔴/🟡 | ... |

## 3. 환류 로그 누락
- [작품명]: 청사진 본문 변경 흔적 N건 / 환류 로그 N건 / 누락 N건
- 누락 항목: [목록]

## 4. 씬 수 표준 위반
| 작품 | 에피소드 | 씬 수 | 판정 |
|---|---|---|---|
| ... | ... | N | 🔴/🟡/🟢 |

## 5. 소품 한도 위반
| 작품 | 에피소드 | 신규 일반 소도구 수 | 도구 목록 | 판정 |
|---|---|---|---|---|
| ... | ... | N | [목록] | 🔴/🟡/🟢 |

## 6. 메모리 ↔ 시스템 룰 일관성
- 메모리 룰 N개 / 시스템 등재 N개 / 불일치 N건
- 불일치 항목: [메모리 룰명 → 시스템 미반영 위치]

## 권장 조치
- 🔴 즉시: [한 줄씩]
- 🟡 다음 세션 진입 전: [한 줄씩]
- 🟢 정보: (보고만)
```

## 작성 원칙
- **읽기 전용** — 어떤 파일도 수정·생성하지 않는다.
- **권장만 제시** — 자동 수정하지 않음. 사용자가 결정.
- **🔴는 즉시 보고** — 발견 시 출력 상단에 강조.
- **표 우선** — 작품·에피소드 단위 테이블로 한눈에 점검 가능하게.
- **간결성** — 6 카테고리 외 다른 것 추가하지 않음 (스코프 제한).

## 동시 호출 흐름 (status + audit)

사용자가 "전체 점검" / "status audit" 등 동시 호출 시:
1. 먼저 `prompts/status.md` 실행 → 진행 단계 보고서 출력.
2. 그 다음 `prompts/audit.md` 실행 → 정합성 검사 보고서 출력.
3. 두 보고서를 분리된 섹션으로 출력 (병합 X).
4. 마지막에 통합 권장 조치 한 단락 추가 (status의 다음 권장 prompt + audit의 🔴 즉시 조치 통합).
