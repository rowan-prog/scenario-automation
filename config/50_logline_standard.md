# 50. 로그라인·타이틀 표준 (2026-08-27 제정 · Fable 구조 개정)

> **한 줄:** 로그라인 = 플랫폼 카탈로그 한 칸(타이틀 영문 ≤50 words · 로그라인 한국어 ≤70 words). **맥락 0인 사람이 한 번 읽고 "누가 누구에게 무엇을 해서 어떻게 됐다"를 자기 말로 다시 말할 수 있어야 한다.** 예시 = `config/50_logline_corpus.md` 179건 — 로그라인·타이틀 작업 진입 시 **전량 정독**(요약 대체 금지). 기계 = `tools/logline_lint.py` · 절차 = skill `/logline` · workflow `logline-round`.

## 0. 제정 사유 (사용자 2026-08-27 verbatim — 이 문서의 판정 기준은 전부 여기서 나온다)

- *"너가 하도 로그라인을 제대로 못써서 예시를 준다."*
- *"기획안, 대본을 누가 읽는다고 생각하나? 내게 보여줄려고 쓰는 것인가? 아니다. 꼼꼼히 읽는 작업자, 다른 기획자 / 대충 읽는 작업자, 다른 기획자 / 이해 잘 못하는 다른 사람들에게 보여주는 것이다. 대상을 생각하라."*
- *"로그라인에 관계/쾌감/핵심트롭/갈등구조/위기/능력/사이다 이런 것들이 다 한 눈에 보여야한다. 중학생이 읽어도 이해 되어야한다. 한문장한문장 꼼꼼히 읽었을 때 재밌고, 대충 띄엄띄엄 읽어도 재밌어야한다."*
- *"수십번 수백번 말한 것들도 지침 업데이트하였다고만 하고, 끔찍하게 이뤄진다. 특히 심각한 우회적/암시적 표현. 1번 더 그 의미, 원관념 등을 파악해내야하는 문장들."*
- **실패 이력:** 29번 〈A Man Who Sees Your Last Day〉 하루 다섯 판 반려(T1 v1 비유·발명 → v2 → v3 토막 → v4 400자 요약 → v5 "13번 길이" 195자·4문장). 구 룰 *"로그라인 = 골격 4단 · 13번 길이(4문장·150자)"*는 **카탈로그 슬롯 규격이 아니었다** → 폐기, 그 4단 문단은 §8 '도입 문단'으로 이름을 바꿔 보존.
- **왜 룰을 고쳐도 안 됐나:** 룰 문장만 늘고 **게이트가 없었다.** 내가 쓰고 내가 "직관적이다" 판정하면 맥락을 아는 내가 통과시킨다. 그래서 이 표준은 룰이 아니라 **절차(§7)가 본체**다 — 후보는 별도 유닛이 쓰고, 되감기는 haiku가 재고, 7요소는 sonnet이 세고, 메인은 고르기만 한다.

## 1. 독자 3종 — 누가 읽나 (대상을 생각하라)

| 독자 | 읽는 법 | 이 독자가 통과시키는 문장 |
|---|---|---|
| **꼼꼼히 읽는 작업자·기획자** | 한 문장씩 다 읽는다 | 문장마다 사건이 있다. 설명·분위기 문장 0. 읽으면 "오 대박" 소리가 난다 |
| **대충 읽는 작업자·기획자** | 명사만 훑는다 | **명사만 주워도 이야기가 선다** — 관계 명사(전남친의 삼촌) · 트롭 명사(위장 결혼) · 반전 명사(왕좌) |
| **이해 잘 못하는 사람** | 한 번 읽고 끝, 되돌아가지 않는다 | **되감기 0** — 비유·암시·원관념 해독·"이게 무슨 뜻이지" 0. 중학생 어휘 |

판정 = **셋 다 통과.** 사용자(나)에게 보여주려고 쓰는 게 아니다 — 사용자는 맥락을 다 알아서 내 문장을 통과시킨다. 기준은 **맥락 0인 세 번째 독자**고, 그 프록시가 `plain-reader`(haiku·effort low · §6)다.

## 2. 한눈에 보여야 하는 7요소

**관계 / 쾌감 / 핵심 트롭 / 갈등 구조 / 위기 / 능력 / 사이다.**

- 각 요소는 **이름으로**(명사·동사) 박힌다. 라벨로 박는 게 아니다 — "사이다"라는 단어 ✗ → 사이다인 **사건** ○ (*"억만장자가 된 아들이 나타나기 전까지"*).
- 작품에 없는 요소(로맨스물의 능력)는 비운다. **있는데 안 보이면 FAIL.** 엔진에 해당하는 요소(관계·핵심 트롭·쾌감)는 항상 있어야 한다.
- 코퍼스 실물 대조:

| 요소 | 코퍼스에서 이렇게 박혀 있다 |
|---|---|
| 관계 | *전 남자 친구의 삼촌* · *의붓언니의 약혼자* · *아빠의 절친* · *아들의 약혼녀* · *전 남편의 친구를 콜보이로* |
| 쾌감 | *억만장자가 된 아들이 나타나기 전까지* · *그 남자가 왕좌에 앉아 있었다* · *남편은 제국의 진짜 지배자였다!* |
| 핵심 트롭 | *위장 결혼* · *삼 년 전으로 회귀* · *하룻밤* · *정체를 숨긴* · *계약 결혼* · *대리 신부로 팔려간* |
| 갈등 구조 | *다섯 남자를 한 명씩 공략하며 매혹해야 한다* · *일주일 안에 … 뱀파이어냐 늑대인간이냐 선택해야 한다* |
| 위기 | *살아남으려면* · *들키는 순간 끝장인* · *그녀의 빛이 꺼지기 전에* · *죽어가는 알파* |
| 능력 | *시간을 되돌리는 억만장자* · *유령을 보는 저주* · *자신의 피가 그의 유일한 치료제* · *용의 알을 낳는다* |
| 사이다 | *가짜를 폭로해 모든 것을 되찾는다* · *자신을 짐승으로 만든 신들을 도륙한다!* · *놈들의 세계를 빼앗는다* |

## 4. 문장 골격 5형 (코퍼스에서 뽑았다 — 이 안에서 쓴다)

| 형 | 골격 | 코퍼스 실물 |
|---|---|---|
| **P1 사건 → 다음 날 반전** (2문장) | [처지] + [사건]. [다음 장면], [정체 반전]. | *여동생 대신 제물로 팔려가기 전날 밤, 그녀는 낯선 남자와 하룻밤을 보냈다. 이튿날 아침, 그 남자가 왕좌에 앉아 있었다.* |
| **P2 당한 것 + 반격** (2문장) | [당한 것 관형절] + 주인공 명사구. [조력·수단]으로 [사이다]. | *절친에게 얼굴도 약혼자도 인생도 빼앗긴 레나. 억만장자 노아와 손잡고 가짜를 폭로해 모든 것을 되찾는다.* |
| **P3 한 문장 + 대시 반전** | [처지]가 [수모]를 당한다 — [반전] 전까지. | *가난 속에서 아들을 키워낸 싱글맘이 아들의 약혼녀에게 수모를 당한다 — 억만장자가 된 아들이 나타나기 전까지.* |
| **P4 처지, 선택 + 하필 반전** (1문장·!) | [처지] 그녀, [선택]한 [대상]이 하필 [정체]였다! | *동생에게 죽고 삼 년 전으로 회귀한 그녀, 조용히 살려고 고른 거지 남편이 하필 예언자 모세였다!* |
| **P5 규칙형** | [능력·저주]를 받은 주인공은 [목적] 위해 [매일·기한] [해야 한다]. | *유령을 보는 저주를 받은 그녀는 살아남기 위해 매일 밤 유령 호텔의 미스터리한 주인과 키스해야 한다.* |

공통 법칙: **① 첫 어절 안에 주인공의 처지(당한 것·신분)가 온다 ② 반전·사이다는 문장 끝에 온다(끝이 세다) ③ 사건 하나·반전 하나 — 둘째 사건은 트리트먼트 몫 ④ 연결어(-고·-자·하지만·하필)는 살린다 — 토막 금지(10_writing ⑧ 3차 교정) ⑤ 두 문장이면 길이가 다르다(긴 상승 → 짧은 반전).**

## 5. 어휘 — 허용과 금지

**허용 = 코퍼스에 있는 굳은 말(0.1초에 읽힌다):** 사랑이 싹튼다 · 불이 붙는다 · 시험대에 오른다 · 휘말린다 · 판을 뒤집는다 · 소용돌이 · 갈림길 · 발이 묶인 · 민낯 · 얽히다 · 목줄 · 무덤에 묻는다. **코퍼스에 없는 비유는 쓰지 않는다** — 새 비유를 만들 권한이 없다.

**금지 (하나라도 있으면 FAIL):**
1. **신조 은유·은유 동사** — 침대를 사수 · 기득권을 매장 · 정조준 · 삼키다 · 튀겨내다 · 박살. 판정 = *그 동사를 문자 그대로 그림으로 그리면 틀린 그림이 나오는가.*
2. **개념 라벨** — 욕망의 증명 · 각성 사이다극 · 보험 왕조 · 안목 쾌감 · 히든 아이덴티티극. 판정 = *중학생이 그 단어를 아는가.*
3. **원관념 숨기기** — *"그 말의 진짜 의미를 알게 된다"* · *"모든 것을 바꿀 비밀"* · *"그의 최고 걸작이지만 마지막 장이 될 수도"* — 무엇인지 안 쓰고 **있다고만** 하는 문장. 코퍼스에도 몇 건 있으나(#38·#169·#20) 약한 예다 — 우리는 안 쓴다. 반전을 봉인해야 하면 반전의 *존재*를 말하지 말고 **앞 사건에서 끝낸다**(P1: 하룻밤 → 왕좌).
4. **내부 작업어** — 엔진·구조·컨테이너·비트·훅·락인·결제·무료런·레지스터·트롭·쾌감 (lint 금지어).
5. **관형절 더미** — 40어절 들고 있다가 끝에서 동사 받기. 두 문장으로 쪼갠다.
6. **인용 대사로 시작** — 카탈로그 슬롯에선 금지. 「모욕 대사」 첫 줄은 §8 도입 문단 자리다.
7. **장르 라벨어**(사이다·리벤지극·권선징악) — 라벨 대신 그 사건.

**"세련·품위" 방향 교체 금지** — 코퍼스는 천박하다(*"놈들은 내 찾아낸 벙커를 통째로 빼앗았다"*·*"양아치 의붓오빠가 하필 늑대인간이라고?"*). 그게 규격이다(`00_vertical_dna` 조건 0).

## 6. 되감기 0 테스트 — 판정의 본체

**맥락 0인 사람이 한 번 읽고 "누가 / 누구에게 / 무엇을 해서 / 어떻게 됐다"를 자기 말로 다시 말할 수 있는가.** 못 하면 FAIL. 두 가지로 읽히면 FAIL. 사용자 정의: *"1번 더 그 의미, 원관념 등을 파악해내야 하는 문장"* = FAIL.

- 프록시 = **`plain-reader`(haiku · effort low)**. 똑똑한 모델은 내가 의도한 걸 알아채 줘서 계측기가 못 된다(`20_review` §7 naive-proxy 원리 — 덜 이해할수록 정확). 메인·opus의 "직관적이다" 자가 판정은 **무효**.
- plain-reader 출력 = 문장별 재진술 또는 `못 함(사유)`. 재진술이 원문과 다른 이야기면 그것도 FAIL(두 갈래).
- 이 게이트는 로그라인만이 아니라 **한국어 산출물 전부**(기획안 전 문장·트리트먼트·셀링포인트·작가 코멘트·반박서)에 발송 전 필수(CLAUDE.md 룰 7 · skill `/plain-gate`).

## 7. 절차 — skill `/logline <작품번호|경로>` · workflow `logline-round`

메인은 후보를 **직접 쓰지 않는다**(생산↔판정 분리 · `20_review` §7). 단일 agent 1회 호출도 금지 — 아래 순서대로.

| 단계 | 유닛 | 모델·effort | 입력 → 출력 |
|---|---|---|---|
| 0 정독 | 메인 | — | 이 문서 + 코퍼스 전량 + 작품 p0/meta(엔진 한 줄·관계·능력 한 줄·반전 허용선·타깃) |
| 1 생성 | `copy-candidate-generator` **×3 병렬** | opus · **low** (창의 = 저사고) | 프레이밍 3종(관계 직격 P2/P4 · 반전 끝맺음 P1/P3 · 규칙형 P5) × 각 15 = 45 |
| 2 기계 | `tools/logline_lint.py --file <후보> --md` | — | FAIL(자수·문장수·금지어) 제거 · WARN 표시 |
| 3 되감기 | `plain-reader` | haiku · **low** | 전 후보 재진술 → `못 함`·두 갈래 제거 |
| 4 요소·캐논 | `logline-auditor` | sonnet · **high** (논리 = 고사고) | 7요소 표 · 골격형 · 캐논 오류(없는 설정·반전 노출·주인공 악역화·원작 이탈) → FAIL 제거 |
| 5 선별 | 메인 | — | 생존 후보에서 **3~5개**(골격형 섞어서) · 사유 한 줄씩 |
| 6 확정 | 사용자 | — | 채택 · 반려 사유는 §0에 환류 |

- 산출 = `projects/NN_slug/NN_slug_logline_round_v{N}.md` (전 후보 + 단계별 판정 + 최종 3~5). 보고 = 절대경로 + 최종 후보만.
- 재작업 트리거: 생존 후보 < 5 → 프레이밍 바꿔 1단계 재실행(같은 프레이밍 반복 금지). 4단계 캐논 오류가 후보 절반 이상 → 캐논 요약이 틀린 것 — 메인이 p0/meta 재확인.
- 같은 절차를 타이틀에도 쓴다(1단계 유형 = 타이틀 · 3단계 = 영문이라 plain-reader가 한국어 역번역 재진술).

## 8. 기획안 안에서의 자리

- **로그라인 필드**(러프 기획안 · 플랫폼 기획안 · 피칭덱 · T1 페이지 · CD1 시트 Overview) = 이 규격 1~2문장. 문서 어디에 있든 같은 규격.
- **도입 문단** = 13번·26번식 「모욕 대사 → 당한 것 → 반전 실물 → 페이오프 + 장르 이름표」 4단 문단(구 "13번 길이 로그라인"). **로그라인이 아니다.** 러프 기획안에서 로그라인 *아래*에 둘 수 있고, 같은 5검사(`10_writing` §D-2-1 ⑧) + 되감기 0 게이트를 받는다. 플랫폼 로그라인 필드에는 안 들어간다.
- 트리트먼트·셀링포인트·시놉시스 문장 = `10_writing` §D-2-1 ⑧ + 독자 3종 게이트. 검수 = `20_review` §1③(체크리스트 = `proposal-spec-auditor`).

## 9. 환류

반려가 오면 **문장을 먼저 본다**(설정이 아니라). 반려 원문을 §0에 verbatim 추가 · 코퍼스에 새 실물이 오면 `50_logline_corpus.md`에 추가하고 `logline_lint.py --stats`로 규격 숫자 재확인 · lint 금지어는 반려 실물에서만 추가(추측 금지). 교정마다 반대편 벽으로 튀지 않는다 — **모델 옆에 놓고 길이·사건 수·명사를 맞춘다**(메모리 [[proposal-prose-five-checks]] 4차).
