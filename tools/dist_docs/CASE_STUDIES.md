## 4. 실패에서 나온 룰 (핵심 4개)

배포 패키지에서 가장 값나가는 부분. 전부 **완성본을 사용자가 읽고 반려한 뒤** 원인을 실측해서 룰과 기계 게이트로 굳힌 것들이다.

### ① "TV드라마 같다" — 8회 LOCK 사이클이 놓친 3중 원인

48화 완본을 사용자가 읽고 내린 판정. 원인을 실측했더니 셋이 겹쳐 있었다.

1. **행사 순회 구조** — 회차마다 공간이 바뀌고 오프닝이 리셋됨. 13화 연속 리셋 오프닝 구간까지 있었다.
2. **net-zero 라운드** — 제거해도 뒤가 무너지지 않는 찌르기 라운드의 반복(빌드업병).
3. **쿨슬롭 레지스터** — 주인공 170라인에 감탄 0, 조력자는 코치봇 톤 72%. **빌런만 잘 써져 있었다** = AI가 주인공·조력자를 망치는 편향.

→ `pacing_lint.py`(공간 경제·절단 구조 6검사) + `register_census.py`(인물별 레지스터) 신설, 룰 §C-2-1·C-4-0·D-5-0 신설.
→ 이후 **컨테이너 법칙**으로 양성 처방까지 도출: 한 컨테이너 = 한 공간 + 한 시간대 9~10화, 점프는 브리지에서만.

### ② 대사 레지스터 — 유창해서 검수를 통과한 함정

50화 각색물 전 대사 코퍼스가 사용자 콜드리드에서 불합격. 완곡·암시·재치 대구·압축 은유가 "스타일"이 아니라 **하드 결함**이라는 판정.
→ "유창한가"가 아니라 **"직설인가"**를 묻도록 검수 질문 자체를 교체. 위트는 EP당 1개 배급제. `esl_hardwords.py` + flat-TTS 프록시 에이전트 신설.

### ③ 히트작 사건 수 실측 — 문서와 실측이 3~4배 어긋나 있었다

러프 기획안이 "8화에 사건 8개·8일·화당 공간 3곳" = 일일극 골격으로 나왔다. 히트작 원본을 세어보니 **50화물의 사건은 2~5개**, 한 사건이 12~41화를 먹고 있었다.
→ 무료 8화 = 사건 **1개**가 정상. 기존 룰 문서의 "아크 10~14개" 조항이 실측과 충돌한다는 것까지 함께 발견되어 개정 안건으로 등록.

### ④ docx 변환 손실 — 유령 결번 오진

외부 대본을 파이썬으로 추출해 "결번·공란 다수"라고 보고했는데, 원본 docx에는 전부 있었다. 표·텍스트박스 안의 대사를 추출기가 통째로 흘린 것.
→ 결손 지적은 **원본 raw XML 대조 후에만** 보고. 이후 두 번째 사례에서 재확인되어 룰이 강화됐다.

## 5. 폐기 사례 (재발 방지용)

폐기 사유를 남기는 것 자체가 자산이다. 예: 9회 재작업 끝에 전량 폐기된 러프 기획 1건의 누적 사유 —
밑바닥 잡역 설정 = 고구마 / 주인공을 조사하는 시선이 화면을 채우면 미스터리 질감 / 프롤로그 몽타주와 "상대가 제도·세계"인 구도 = 숏폼 아님 / 서류·서명·조서 = 소송극 / 8화 내내 공간과 대립 상대가 매 화 바뀌면 돌아올 핵심 쾌감이 없음.

이 목록은 새 기획을 시작할 때 그대로 체크리스트로 쓰인다.

## 6. 이 패키지를 받은 사람에게

위 사례의 작품 본문·캐논은 배포에 포함되지 않는다(IP). 포함되는 것은 **위 판정들이 굳어진 룰·도구·에이전트·메모리**다.
따라서 이 패키지는 "빈 껍데기 워크플로우"가 아니라, 3개월간 완성본을 반려당하며 교정된 판정 기준을 그대로 물려받는 것에 가깝다.
